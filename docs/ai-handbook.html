二、命令详解

/write — 写作(核心)

AI:每次生成 1 次 + 字数不足时最多补写 2 次 · 温度 0.9

三种模式:

① 向导模式(无参数):逐章询问 章数 → 标题 → 登场人物 → 场景(编号=持久/描述=临时不保存)→ 剧情大纲(回车=AI 自动构思)→ 确认后逐章写作。每章自动创建文件,写入 YAML(标题/地点/人物),字数不足 2500 自动补写。

② 批量模式:/write --n 3 --from 1 按大纲写 — 从第 N 章起连续写;每章内容优先取 /outline add 第N章 标题:内容 的章节大纲;;; 分隔可逐章指定。章间自动把上一章结尾 300 字注入下一章作衔接。

③ 续写模式:/write 继续写… 在"当前章节"后追加。

上下文注入(每章一次,见第三节):风格/总纲/章节大纲/当前章全文/近 2 章/卷摘要/前卷梗概/出场人物/场景/世界观前 5/时间线近 5/未回收伏笔/成长/检索结果。

/scene — 场景管理

AI:不参与 · 文件:scenes/*.md

/scene add 青州城门 城墙斑驳,守军盘查 保存持久场景;向导里输编号即选它,写入该场景的章节自动带上完整描述。临时场景(向导里直接描述)不建文件,仅记入该章 YAML。

/char — 人物管理

AI:不参与 · 文件:characters/*.md

/char add 林晚 黑发剑客,外冷内热 创建带模板的档案(身份/外貌/性格/动机/初始设定),可手动补全。写作时按章节 chars 动态注入出场人物档案。

/world — 世界观

AI:不参与 · 文件:world/*.md

/world add 修真境界 炼气筑基金丹 一个领域一个文件。写作时注入前 5 条。

/chapter — 章节管理

AI:不参与 · 文件:chapters/*.md

/chapter new 标题 建章并定位;/chapter go N 切换当前章(决定续写目标);/chapter list 显示标题与当前定位。

/outline — 大纲

AI:不参与 · 文件:outline/arc.md

普通行进总纲;/outline add 第N章 标题:内容 进入「## 章节大纲」区,/write --n 批量时按章号自动取用。

/time — 时间线

AI:不参与 · 文件:timeline.md + novel.json currentTime

/time add 章节 时间点 事件 记一行并把「当前时间点」更新到 novel.json,写作时注入。目前靠人工维护(见待检查项 #6/#9)。

/style — 风格

AI:extract 调 AI(温度 0.3)· 文件:style.md + novel.json style

/style set 快节奏爽文 直接设定;/style extract 样章.md 让 AI 读样章提炼风格指南(视角/句长/描写密度/节奏)写入 style.md。这是调教 AI 文风最直接的手段:风格指南会注入每次写作。

/growth /vault /idea

AI:不参与 · 文件:growth.md / vault.md / notes/ideas.md

成长记录(阶段/章节/描述)、伏笔台账(未回收的会注入写作提示"注意铺垫不要提前揭露")、灵感碎片。

/check [--deep] — 一致性检查

AI:规则部分不调;--deep 调 AI(温度 0.3)

规则引擎:时间线条数/未回收伏笔/章节数/章节 YAML 完整性。--deep 把最近 3 章 + 人物 + 时间线 + 伏笔喂给 AI,检查人设崩坏/时间错乱/战力失衡/伏笔问题。规则部分只统计,不做真正的时间倒流检测(待检查项 #6)。

/reader — AI 模拟读者

AI:调 AI(温度 0.8)

以追更读者口吻评最近 3 章:观感/爽点毒点/节奏/断章/期待。温度最高,鼓励发散。

/summary — 卷摘要

AI:gen 调 AI(温度 0.3)· 文件:summaries/volN.md

每 10 章一卷。gen 读本卷全部章节(截断 20000 字符)让 AI 提炼 5 点摘要(剧情线/转折/人物状态/伏笔/结尾)。这是 100 万字一致性的核心:写作时自动注入当前卷摘要 + 前卷梗概,AI 不会遗忘早期剧情。

/search — 全文检索

AI:不参与 · 本地扫描全部章节

/search 玉佩 返回出现位置+行上下文(每文件最多 3 条,共最多 10 条)。写作指令里写 [查:玉佩] 会在写作前自动检索并注入。

/export /stats /config /help /quit

AI:不参与

导出全书(md/txt,含书名);字数统计(纯正文去空白);模型/风格配置;详细帮助(/help write 有用法+示例);退出。

三、AI 调教机制(如何调教 AI)

3.1 模型配置链

配置项位置实际生效?
provider / modelnovel.json model 或 /config✅ 生效(deepseek/openai/ollama/zhipu/mock)
apiKeynovel.json model.apiKey 或环境变量 <PROVIDER>_API_KEY✅ 生效(前者优先)
temperaturenovel.json model.temperature❌ 不生效 每个调用点硬编码 0.9/0.3/0.8,配置被覆盖
maxTokensnovel.json model.maxTokens⚠️ 默认 4000 中文 3000 字约需 4000-5000 token,可能截断
stylenovel.json / style.md✅ 生效(注入每次写作)

3.2 写作上下文组装(每次 /write 注入什么)

层内容估算 token
身份「你是小说写作助手,创作《X》,面向中文网文读者…」+ 当前时间点~80
固定层风格指南(style.md)+ 总纲 + 本章大纲~300-800
金字塔 1目标章节全文~2000-4500
金字塔 2最近 2 章全文~4000-9000
金字塔 3本卷摘要(若有)~500
金字塔 4前卷梗概(近 2 卷摘要 + 更早浓缩)~400-1200
按需出场人物档案(chars 驱动)+ 本章场景 + 世界观前 5 + 时间线近 5 + 未回收伏笔 + 成长 + [查:] 检索~1000-3000
指令你的写作指令 + 「要求:直接输出正文…单章 3000±500」~100

合计约 8000-19000 token/次(不含输出)。DeepSeek 上下文 64K 起步,单次写作预算充足;但「当前章全文 + 近 2 章全文」无截断,若用户反复续写同一章导致单章膨胀,会吃掉预算(待检查项 #5)。

3.3 温度策略(任务分级)

任务温度设计意图
写作 / 补写0.9鼓励创意与文风变化
AI 读者 /reader0.8发散,像真实读者各抒己见
风格提取 /style extract0.3低温度,忠实提炼样章特征
深度校验 /check --deep0.3低温度,事实性检查要稳定
卷摘要 /summary gen0.3低温度,忠实浓缩不发挥

3.4 各 AI 任务的 prompt 要点

【写作系统提示】你是小说写作助手,创作《X》…面向中文网文读者,保持人物设定与时间线一致。
[注入各层内容]…【写作指令】{你的输入}
要求:直接输出正文,不要解释;保持风格一致,章末留钩子;对话符合人物设定;单章 2000-4000 字。

【补写提示】本章目前约 N 字,目标 3000 字左右(±500 均可)。请继续扩写…如果剧情已自然收束,可以适度收尾,不要为凑字数硬写。

【风格提取】以下是样章,请提炼可用于 AI 续写的风格指南(视角/人称/句长/描写密度/对话风格/节奏特点/常用修辞),精炼中文要点。

【深度校验】请审阅最近章节:1)人物设定是否崩坏 2)时间线是否错乱 3)战力/能力是否失衡 4)伏笔是否提前揭露或遗漏。输出问题清单和修改建议。

【AI 读者】你是追更网文读者,给出:整体观感/爽点毒点/节奏问题/断章是否抓人/下一章期待。口语化。

【卷摘要】生成卷摘要:1)主要剧情线 2)关键事件转折 3)人物状态变化 4)埋下伏笔 5)卷末状态。300-500 字。

四、限制与安全

  • 零外部写入:所有读写都在当前作品目录内(向上查找 novel.json 定位),这是硬约束。
  • 命令白名单:只有注册的 20 个命令可执行,无任意代码执行能力;AI 只能"输出文本",由程序写入文件。
  • 模拟模式:无 API key 自动降级 mock,不产生任何网络调用和费用。
  • 字数/元数据约束:写作指令内置 3000±500 与元数据要求,通过 prompt 约束而非硬校验(补写仅在下限之下触发)。
  • 权限系统现状:src/permission.ts 实现了 opencode 式 ask/allow/deny 评估器,但没有任何命令接入——novel.json 里的 permissions 字段目前是摆设(待检查项 #3)。

五、待检查清单(不合理点候选,请逐条审)

#1 max_tokens 默认 4000,可能截断 3000 字章节

现状:llm.ts 默认 4000,所有调用点未传;中文 3000 字 ≈ 4000-5000 token,DeepSeek 一次输出可能被截断,导致章节缺尾巴。
建议:默认提到 8000;或在 /config 暴露 max-tokens 配置项。

#2 novel.json 的 temperature 配置不生效

现状:每个调用点硬编码 0.9/0.3/0.8,配置值被 opts 覆盖,用户调不动。
建议:调用点去掉显式温度,统一走配置(任务级默认 + 用户覆盖);或在 /config 里暴露。

#3 权限系统是死代码

现状:permission.ts 未被任何命令引用;permissions 配置写进 novel.json 但无效。
建议:要么接入(对写文件/删除/导出等操作做 ask/allow/deny),要么删除以免误导。

#4 自由输入写作不保存文件

现状:直接输入文字 = AI 写作,但结果只显示在屏幕,不落盘;README 文案「直接输入 = 写 1 章」有误导。
建议:自由输入也追加到当前章(与 /write 一致),或明确标注「即兴对话,不保存」。

#5 当前章全文注入无截断

现状:同一章反复续写会越来越长,每次全量注入,上下文预算被单章吃掉。
建议:当前章只注入最近 4000 字 + 该章开头 500 字锚点。

#6 /check 规则引擎不做时间倒流检测

现状:只统计时间线条数;设计文档里的「角色 3 天前在 A 城今天在 B 城 → 报警」未实现。
建议:从章节 YAML time/location 构建全时间线,检测时间倒流与地点跳跃矛盾。

#7 批量写入已有内容的章节会追加而非覆盖

现状:/write --from N 若第 N 章已有正文,newChapter 复用文件 + append 追加,可能重复内容。
建议:检测到已有内容时警告并要求确认,或改为覆盖。

#8 人物回退注入顺序不稳定

现状:chars 为空时回退"前 3 个人物",readdir 顺序无保证。
建议:按文件名排序取前 3,或按最近出场排序。

#9 向导没有时间点输入

现状:向导配置标题/人物/场景/大纲,但每章的时间点(time)只能事后 /time 或手改 YAML,「故事=人物×场景×时间」缺一环。
建议:向导加「时间点」步骤,写入 YAML 并自动推进 currentTime。

#10 导出文件名含书名,非法字符会失败

现状:export-{书名}.md,书名含 / \ : * ? " < > | 时 Windows 写入失败。
建议:文件名净化或固定 export.md。

#11 旧文件 src/commands.ts 残留

现状:v0.2 的单文件命令版还在项目里(未被引用),与新 src/commands/ 并存,易混淆。
建议:删除。

#12 卷摘要生成截断 20000 字符

现状:/summary gen 只喂本卷前 20000 字符,卷超过 10 章或章节很长时,卷尾内容不进摘要。
建议:分块摘要(每章先摘要再合并),或按实际卷内容比例截断。

#13 上下文无总预算控制

现状:各层叠加,极端情况(章节全量 + 世界全量)可能超出模型上下文。
建议:组装后估算 token,超预算时逐层降级(先丢世界观→再丢近章)。
